07 · Real Logic / Interlock

已实现案例：Control On 到主气压放行

维修门供电、门反馈、安全继电器反馈、主阀输出和压力反馈均纳入周期检查；故障通过标准 Event 与 ControlOn 接口处理。

正常路径

ControlOn 标准 AddOn 返回 OK 后，只有两个门反馈、两路门锁输出和维修门安全继电器 `_000K981_Y32` 都成立，主气阀才允许上电。

_000S901按下 Control On

电气安全回路正常后，标准 AddOn 给出 OK。

_000K980 / 981维修门供电

FB_MaintenanceDoorControl 驱动两路输出。

5 s + 1 s确认安全链

A/B 门反馈 5 s 内成立；随后 `_000K981_Y32` 需在 1 s 内成立。

_000K085A主气阀上电

维修门 Release 成立后才允许主压力输出。

HIGH XOR LOW压力状态确认

高低压不能同时出现；切换过程最长 5 s。

故障闭环

EVENT_MAINTENANCE_DOOR_NOT_LOAKEDA/B 门或 `_000K981_Y32` 未按时到位：锁存报警，并在 AdditionalInfo 标明具体信号。
EVENT_PRESSURE_NOT_HIGHER要求高压后 5 s 未到：关闭 _000K085A。
EVENT_PRESSURE_NOT_LOWER撤压后低压未到，或 HIGH / LOW 同时出现：报警。
ParImm.UserEnableControlOn := FALSE通过标准 AddOn 的正式接口撤销 Control On，不抢写内部输出。

软件联锁不替代安全继电器 / 安全 PLC。接线、响应时间和故障注入仍需真机安全验证并由用户批准。

08 · Learning Loop

BMK 改名后的三层残留

CpStudio 更新 BinIo 变量后，旧名字可能仍留在 EtherCAT I/O Mapping 与 Symbol Configuration。AI 处理的不是单个编译错误，而是跨配置层的一致性。

名字变化只是表面

变量在低代码平台中改名并导出，PLC ST 可能已经是新名字，但生成器外侧的 IDE 配置仍指向旧符号。

旧符号bus_000SK010A1_Channel_6
→
新 BMK_000B085A_LOW
处理结论BMK 改名后固定核对生成变量、I/O Mapping 与 Symbol Configuration；编译错误只是三层不一致的结果。

三层一致性审计

1BinIo / 生成变量CpStudio 输出的新变量名、类型和描述COMPARE
2EtherCAT I/O Mapping活动通道重映射；已停用通道清除旧映射MCP
3Symbol Configuration官方 REST 选中新符号、取消旧签名并读回REST
66 → 0

最初骨架清理：旧 ST 对象与 A1 映射分层定位。

33 → 0

批量改名：16 个活动通道、17 个停用通道及符号配置。

1 → 0

单个 C1 小改动：按同一套路快速定位并消除。
